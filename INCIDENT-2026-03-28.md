**Date:** 2026-03-28
**Responder:** Jeong-Ryeol
**Environment:** Ubuntu 24.04 Home Server (Docker-based microservices)
**Severity:** High
**Status:** Resolved
**Related:** [Incident #1 (2026-03-18)](./README.md) - Same attacker, different vector

---

## Executive Summary

On March 28, 2026, a Monero (XMR) cryptominer was detected on the same server as Incident #1 (March 18). Despite remediation of the Redis attack vector from Incident #1, the attacker returned using a **different entry point** - a publicly exposed Next.js application port with a Server Action Remote Code Execution (RCE) vulnerability.

The cryptominer was consuming **600% CPU** across cores with temperatures reaching **94 degrees celsius**. The attacker deployed the same binary (`/tmp/npm_update`), same mining pool, and same wallet address as Incident #1.

This incident highlights that **patching one vector is insufficient** when multiple services remain exposed to the internet.

## 3. Analysis

### Attack Vector: Next.js Server Action RCE

Unlike Incident #1 (Redis), this attack exploited the **Next.js application directly**.

#### Evidence from Container Logs
```
SyntaxError: missing ) after argument list
    at Object.Function [as get] (<anonymous>)

[Error: Failed to find Server Action "default". This request might be from
an older or newer deployment. Original error: Cannot read properties of
undefined (reading 'workers')]
```

The `Object.Function [as get]` error indicates the attacker was injecting code via the JavaScript `Function()` constructor through Next.js Server Actions, achieving Remote Code Execution (RCE).

### Process Hierarchy
```
PID 3296927 (next-server v15.2.2 - arkmarket container)
  └── PID 1870803 (/tmp/npm_update - XMR miner, 581.8% CPU)
```

### Attack Chain
```
Internet
  → Port 3003 (bound to 0.0.0.0, no firewall)
  → Next.js 15.2.2 Server Action endpoint
  → Function() constructor RCE
  → Binary downloaded to /tmp/npm_update (8MB)
  → Cryptominer executed, connecting to 31.220.80.26:3333
```

### Why Incident #1 Fixes Were Insufficient

| Incident #1 Fix | Status | Gap |
|-----------------|--------|-----|
| Redis password added | Applied | N/A (different vector) |
| Redis bound to 127.0.0.1 | Applied | N/A (different vector) |
| iptables rules for DB ports | Applied | Did not cover port 3003 |
| arkmarket port binding | **NOT FIXED** | Still `0.0.0.0:3003` |
| Next.js version update | **NOT DONE** | Still on vulnerable 15.2.2 |

## 6. Containment & Eradication

### Step 1: Stop Infected Container
```bash
docker stop arkmarket-arkmarket-1
```

### Step 2: Update All Docker Compose Files
Changed all `0.0.0.0` port bindings to `127.0.0.1`:

```yaml
# Before (vulnerable)
ports:
  - "3003:3000"

# After (hardened)
ports:
  - "127.0.0.1:3003:3000"
```

Applied to: arkmarket, mysql, postgresql, portainer, raid-together, bitcoin-prediction, discord-bot

### Step 3: Restart All Containers
```bash
cd ~/docker/mysql && docker compose down && docker compose up -d
cd ~/docker/postgresql && docker compose down && docker compose up -d
cd ~/docker/portainer && docker compose down && docker compose up -d
cd ~/docker/raid-together && docker compose down && docker compose up -d
cd ~/docker/bitcoin-prediction && docker compose down && docker compose up -d
```

### Step 4: Migrate PM2 Discord Bot to Docker
```bash
pm2 stop discord-bot && pm2 delete discord-bot
docker start raid-together-bot
```

### Step 5: Delete Infected Image & Clean Rebuild
```bash
docker rm arkmarket-arkmarket-1
docker rmi arkmarket-arkmarket

# Update Next.js 15.2.2 → 16.2.1
# Regenerate package-lock.json
cd ~/docker/arkmarket && docker compose build --no-cache
cd ~/docker/arkmarket && docker compose up -d
```

### 7.2 Next.js Version Upgrade
- **Before:** Next.js 15.2.2 (Server Action RCE vulnerability)
- **After:** Next.js 16.2.1 (latest stable)

- Deleted infected image

## 10. Lessons Learned

### What Went Wrong
1. **Incident #1 fix was too narrow** - Only the exploited Redis was hardened; other services remained exposed
2. **No comprehensive port audit after Incident #1** - Would have caught the 5 other `0.0.0.0`-bound services
3. **Next.js not updated** - Known vulnerabilities in 15.2.2 were not patched
4. **Same attacker returned within 10 days** - Indicates the server was bookmarked/indexed by the attacker

### What Went Right
1. **Docker containment worked again** - Attacker confined to container, no host compromise
2. **Faster response** - 15 minutes vs 30 minutes in Incident #1
3. **Comprehensive fix this time** - All 7 services locked down to `127.0.0.1`
4. **Clean rebuild** - Infected image fully replaced, not just process killed

### Permanent Fixes Applied
1. **All Docker ports bound to `127.0.0.1`** - No direct internet exposure
2. **All external access via Nginx reverse proxy only** - Single point of entry (80/443)
3. **Next.js upgraded to 16.2.1** - Server Action vulnerability patched
4. **PM2 discord-bot migrated to Docker** - Consistent management

### Remaining Recommendations
1. **Automated monitoring** - Set up Grafana CPU alerts to detect mining earlier than fan noise
2. **Docker network isolation** - Use internal Docker networks instead of host port mapping where possible
3. **Regular dependency updates** - Monthly audit of all container base images and application dependencies
4. **Read-only container filesystems** - Use `read_only: true` in docker-compose to prevent binary drops in `/tmp`
5. **Drop container capabilities** - Use `cap_drop: [ALL]` to minimize container privileges
